  1. src/db/client.ts：Pool + Drizzle インスタンス

  含める内容（高レベルだけ、コードはあなたが書く）：

- pg.Pool を生成
  - connectionString: process.env.APP_DATABASE_URL（ADMIN ではなく APP：RLS
  対象になる）
  - 最大接続数（max）の設定。POC なら 10 で十分
  - idleTimeoutMillis、connectionTimeoutMillis の設定（任意、デフォルトでも可）
- env が未設定なら throw new Error(...) で早期失敗
- drizzle({ client: pool, schema }) で Drizzle インスタンス生成
  - schema は src/db/schema/index.ts（後述）から re-export して渡す
- pool と db を named export
  - pool は graceful shutdown（プロセス終了時の pool.end()）で使う
  - db がアプリケーションの全 DB アクセスのエントリ

  ▎ 注意：
  ▎ - process.env.APP_DATABASE_URL を直接参照するなら、起動時に値を検証（空・undefined
  ▎ を弾く）
  ▎ - ここで Pool を作ると、test 環境で test DB
  ▎ を指したいときに上書きできない問題が出ます。M5 や M6 で test
  ▎ 用の戦略が必要になるかも（今は気にせず POC 進行）

  1. src/db/with-tenant.ts：本マイルストンの主役
  
  含める内容：

  3-a. tenant_id の検証（Zod）
  
- z.string().uuid() の schema を 1 行
- 関数の入口で parse()、不正なら ZodError がスロー
- parse ではなく safeParse でカスタムエラーを投げる選択肢もある（学習材料）

  3-b. withTenant の関数シグネチャ

  async function withTenant<T>(
    tenantId: string,
    callback: (tx: ???) => Promise<T>
  ): Promise<T>
  
- 引数：tenantId（string、UUID 検証する）と callback
- 戻り値：callback の戻り値をそのまま返す（T）
- tx の型：Drizzle の transaction が callback に渡す引数の型。型推論するか、Drizzle  
  の PgTransaction<...> から拝借
  - 型を完全に書こうとすると複雑になりがち。最初は Parameters<...>[0]
  で抜き出すか、db.transaction の引数推論に任せて (tx) => ...
  のままで動くようにする手も

  3-c. 実装本体

  1. tenantId を UUID 検証（不正なら ZodError）
  2. db.transaction(async (tx) => {
       await tx.execute(sql`SELECT set_config('app.tenant_id', ${tenantId}, true)`);
       return callback(tx);
     })
  3. db.transaction の戻り値をそのまま return

  注意点：

- ${tenantId} は Drizzle の sql テンプレート内ではパラメータ化される（SQL injection
  安全）
- set_config の第 3 引数 true で LOCAL 相当
- 例外が callback 内で発生すれば db.transaction が自動で ROLLBACK し、SET LOCAL
  の効果も消える

chore(config): use ADMIN_DATABASE_URL for drizzle-kit to support db:reset

  The earlier switch to MIGRATOR_DATABASE_URL is correct for production where
  the role survives between deploys, but breaks `pnpm db:reset` because migrator
  is created by 0002 itself — there's nobody to authenticate as on a fresh DB.
  ADMIN_DATABASE_URL keeps the dev workflow simple. Production deploys can
  switch back to MIGRATOR after the first apply.

fix(db): use valid UUIDv7 strings in dev seed so they pass z.uuidv7()

  The previous "readable" UUIDs (11111111-..., aaaaaaaa-...) failed strict v7
  validation in Zod 4 (version digit and variant bits). Replaced with valid v7
  strings while keeping the last 12 chars human-readable for verification queries:
    tenant-1: 01900000-0000-7000-8000-000000000001
    tenant-2: 01900000-0000-7000-8000-000000000002
    alice:    01900000-0000-7000-8000-aaaaaaaaaaaa
    bob:      01900000-0000-7000-8000-bbbbbbbbbbbb
    carol:    01900000-0000-7000-8000-cccccccccccc
    posts:    .....-dddddddddddd / -eeeeeeeeeeee / -ffffffffffff

  Required so withTenant accepts these IDs from app code without ZodError.
