  再考点 1：RLS 違反は 読み書きで分けて考える

  RLS 違反はコンテキストで HTTP status が変わります。

  ケース A：READ 系（GET /posts/:id）

- ID が DB に存在するが別テナントのもの
- RLS で見えない → アプリから見ると「存在しない」と等価
- 404 Not Found が正解（403 だと「そのテナントに存在する」を漏らしてしまう）
- → 存在の漏洩を防ぐため 404 で揃える

  これはあなたが書いた「自テナントの post を SELECT したが対象 ID
  が存在しない」と同じ扱い。

  ケース B：WRITE 系（越境 INSERT、越境 UPDATE）

- クライアントが「自テナントを名乗りつつ別テナントの user_id を参照」みたいな越境攻撃
- WITH CHECK で弾かれる
- これは 「クライアント入力が業務ロジック上正しくない」 ので：
  - 400 Bad Request（広めの 4xx）
  - 422 Unprocessable Entity（フォーマットは正しいが意味的に処理不能）
  - 場合によっては 403 Forbidden（権限不足）
  - 404 は不自然：書き込み先が「見つからない」というよりは、「指定した参照が無効」

  実装としては：

- DB エラーコード（PostgreSQL の 42501 など）をミドルウェアで拾って 400 にマッピング
- もしくは withTenant 内で try/catch して RLS 違反を BadRequestError に変換

  改訂版の表

  ┌────────────────────────────────┬─────────────────────────────────────┐
  │             ケース             │             HTTP status             │
  ├────────────────────────────────┼─────────────────────────────────────┤
  │ RLS 違反による READ で見えない │ 404（存在を漏らさない）             │
  ├────────────────────────────────┼─────────────────────────────────────┤
  │ RLS 違反による WRITE 拒否      │ 400 / 422（クライアント入力エラー） │
  └────────────────────────────────┴─────────────────────────────────────┘

  再考点 2：x-tenant-id 不在は 401 が慣習

  理由：

- HTTP の慣習：認証情報の不備は 401、入力の不備は 400
- POC では x-tenant-id が認証情報の代理（本番では JWT）
- 「必要な認証情報が無い」= 401 Unauthorized

  実用上：

  401 Unauthorized          ← 認証情報が無い、無効
  403 Forbidden             ← 認証情報はあるが、権限不足
  400 Bad Request           ← リクエスト自体が壊れている

  x-tenant-id 不在は、本番では JWT 不在に対応するので 401。

  ▎ POC で 400 と書くのも理解はできます（「ヘッダーは『入力』だから
  ▎ 400」という解釈）。応募リポでは 401 にしておくと、本番想定との整合性が取れる。

  ---
  詰まりやすいポイント

- @hono/zod-validator の戻り値：c.req.valid("body") ではなく
  c.req.valid("json")（POST/PUT body の場合）
- c.json() は Content-Type を上書き：application/problem+json を返したいなら
  c.body(JSON.stringify(...), status, { "Content-Type": ... }) を使う
- c.set / c.get の型：Hono のジェネリック Variables を設定しないと c.get("tenantId")
  が unknown
- ZodError の構造：v4 では error.issues が標準。error.flatten() で { fieldErrors,
  formErrors } 形式に
- PostgreSQL のエラーコード 42501：RLS 違反は 42501。code
  フィールドで判定（メッセージ文字列で判定するのは脆弱）
- factory パターンの罠：createApp() を呼ぶ前に pool / db が初期化される（client.ts は
   import 時に走る）。テストで差し替えたいときは要工夫
